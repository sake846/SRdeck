# SDRプラグイン標準サービス設計

## 1. 目的

この文書は、多種多様な復調プラグインを継続的に追加するために、基盤の標準サービス、
方式非依存ライブラリ、個別プラグインの責務境界を定める。

基本原則は次のとおりとする。

> 資源管理、実行制御、汎用信号変換は基盤が標準化し、信号方式の意味と受信判断はプラグインが所有する。

標準サービスは新規プラグインの既定経路とするが、特殊な広帯域処理、検出器とチャネライザの融合、
その他の方式固有最適化を妨げないよう、生 IQ を受信する経路を維持する。

## 2. 所有権の判定基準

次のいずれかに該当する処理は、標準サービスまたは方式非依存ライブラリの候補とする。

- 3 方式以上で同じ意味と入出力を持つ。
- SDR、ファイル、音声、メモリ、CPU 時間など共有資源の調停が必要である。
- 上限、公平性、障害隔離、タイムスタンプの一貫性を基盤が保証する必要がある。
- SIMD、GPU、バッファ共有など、一括最適化の効果が大きい。
- 通信規格のフレームやプロトコルの意味を知らずに実装できる。

次のいずれかに該当する処理は、個別プラグインが所有する。

- 規格固有のプリアンブル、同期語、シンボル配置またはフレーム構造を解釈する。
- 検出率と誤検出率、追跡と再捕捉などの方式固有トレードオフを含む。
- CRC、FEC、スクランブルなどを適用するビット範囲と順序を規格が定める。
- 共通化すると方式固有オプションが主要 API を占める。
- 規格改訂またはプラグインの受信戦略だけを理由に変更される。

## 3. 標準アーキテクチャ

```text
SDR / IQ ファイル
    ↓
入力管理、ブロック化、時刻、連続性、障害隔離        基盤
    ↓
共有生 IQ ブロック
    ├─ 生 IQ 配送                                 標準サービス
    └─ 周波数変換、帯域制限、レート変換             標準チャネルサービス（任意利用）
            ↓
       チャネル IQ ブロック
            ↓
検出、同期、復調戦略、フレーム化                    個別プラグイン
            ↓
CRC / FEC アルゴリズム                              共通部品を利用可能
適用範囲、プロトコル解析、履歴、UI                   個別プラグイン
```

DSP のホットパスで 1 サンプルごとの仮想呼び出しやプロセス間呼び出しを行ってはならない。
配送と標準変換は `Span<T>`、`Memory<T>` またはリースされたブロックを単位とし、定常処理中の
割り当てとコピーを最小化する。

## 4. 基盤とSDKが提供する標準機能

現行の公開形態を次に示す。将来候補を現行のホストサービスとして記載してはならない。

| 機能 | 現行の提供形態 | プラグインが指定・所有するもの |
|---|---|---|
| 入力・IQ 配送 | ホストと `IIqBlockConsumer`。ブロック寿命、有界キュー、ドロップ、例外隔離 | キュー希望値、受信能力 |
| チャネルストリーム | ホストと `IPluginChannelBlockConsumer`。NCO、帯域制限、レート変換、群遅延 | 中心周波数、帯域、出力レート、品質方針 |
| サンプル時刻・連続性 | IQメタデータ、`MapOutputToSource`、SDKの `IqStreamContinuityTracker` | リセット対象となる方式固有状態 |
| メモリ・リース | `IIqBlockLease`、`IChannelIqBlockLease` とホスト診断 | 呼出し期間内の処理と、必要時の明示的コピー |
| IQ キャプチャ | SDKの有界履歴バッファと `BoundedIqWavWriter` | 保持量、トリガー、保存操作、診断メタデータ |
| 診断・メトリクス | `IPluginMetrics`、`IPluginRuntimeDiagnostics` | 方式固有値、棄却理由、総合状態への解釈 |
| 音声 | `IPluginAudioSink` | PCM生成、音量、音源状態、ストリーム連番 |
| 同調 | `IPluginTuningService` | 対象周波数、帯域、最小入力条件 |
| 設定・データ | `IPluginSettingsStore` と名前空間化データディレクトリ | スキーマ、検証、移行、データモデル |
| ログ・受信通知音・時刻 | `IPluginLogger`、`IPluginNotificationService`、`TimeProvider` | イベントID、重大度、安全な説明、通知音の発生条件 |

標準チャネルサービスが利用できないホスト、または標準処理が方式要件を満たさない場合、
プラグインは生 IQ 能力へフォールバックできる。プラグインは標準サービスの具象実装を参照せず、
Contracts の能力とインターフェースだけを使用する。

## 5. 方式非依存 DSP ライブラリ

`SRdeckCore.SignalProcessing` は、基盤サービスとプラグインの双方から利用できる小さなDSP部品を所有する。
現行の公開部品は次のとおりである。

- 複素周波数変換器
- 有界CICデシメータと補償フィルター
- polyphase有理比リサンプラ
- Radix-2 FFT
- IQサンプルリングバッファ
- 公開境界用の複素サンプル型

追加する共通部品は、3方式以上で同じ意味と入出力を持つことを確認する。フィルター、AGC、相関器、
PLL、タイミング回復、CRC／FECなども候補になり得るが、現行ライブラリに存在しない部品を提供済みとして扱わない。

部品は万能復調器や固定パイプラインにまとめず、状態の `Reset`、群遅延、入出力レート、
割り当て特性を明示した組み合わせ可能な形で提供する。

## 6. 個別プラグインが所有するもの

- 対象チャネルとプロファイルの意味
- 信号検出、プリアンブル探索、同期候補の管理
- 搬送波・タイミング回復の方式固有構成とループ利得
- シンボル判定、複数仮説、再捕捉、弱信号時の判断
- フレーム構造、ビット順、スクランブル、CRC/FEC の適用範囲
- プロトコル解析、復号、重複排除、ドメインモデル
- 方式固有設定、履歴、集計、エクスポート、UI
- 標準処理段階へ追加する方式固有診断と、その状態解釈

## 7. 契約とプロジェクト境界

| プロジェクト | 責務 |
|---|---|
| `SRdeckPlugin.Contracts` | 安定 ABI、ライフサイクル、サービスインターフェース、ブロック契約 |
| `SRdeckCore.SignalProcessing` | 高性能な方式非依存 DSP 部品 |
| `SRdeckPlugin.Sdk` | 直列化・補償停止・再試行可能な後処理を備えた共通ライフサイクル、連続性追跡、診断、JSON Lines履歴、`BoundedIqWavWriter`による上限付きIQ WAV保存、ベンチマーク支援 |
| `SRdeck` | 標準サービスの実装、共有資源、スケジューリング、障害隔離 |
| `SRdeckPlugin.<方式名>` | 方式固有受信戦略、フレーム、プロトコル、結果、UI |

`SRdeckPlugin.Contracts` に DSP の具象実装を含めない。サービス契約は後方互換な能力追加として発展させ、
`SRdeckCore.SignalProcessing` と `SRdeckPlugin.Sdk` は通常のバージョン付き依存関係として扱う。

## 8. 現行実装と互換性

現行ホストは、生IQ配送、同期した複数チャネル配送、同一処理条件のチャネル共有、複数プラグイン実行、
CPU SIMDおよびGPU対応の標準チャネル処理を実装する。アクセラレーションの選択、校正値、ネイティブAPI、
カーネル構成など変動しやすい実装詳細は本アーキテクチャの規範にせず、ホスト実装と回帰試験を正本とする。

追加プラグインの同調対象が主プラグインの現在の通過帯域外にある場合は、主同調を変更せず追加起動を拒否する。
アクセラレーション経路を切り替える場合も、ブロック順序、リース寿命、群遅延、サンプル位置、
不連続通知および方式固有復調の所有権を変更してはならない。

後方互換性のため生IQ契約を削除しない。標準チャネルを利用できないことだけを理由に、
生IQフォールバックを許可したプラグインまたは生IQ専用プラグインをロード失敗にしてはならない。

## 9. 共通適合試験

すべての IQ 処理プラグインと標準チャネル処理は、少なくとも次を検証する。

- IQ ブロック境界を変更しても受信結果が変わらない。
- 対応する最大入力条件で継続的に実時間処理できる。
- 定常ブロック処理の割り当て量、コピー回数、最大一時メモリを測定できる。
- 世代変更、不連続、同調・レート変更後に旧 DSP 状態を使用しない。
- 入力ドロップ後に旧ブロックと新ブロックを連続データとして扱わない。
- 群遅延補正後のフレーム時刻と絶対サンプル位置が許容誤差内である。
- 無信号、飽和、非有限値、不正メタデータで基盤を停止しない。
- 停止後にワーカー、リース、ファイル、サービス購読を残さない。
- 既知 IQ ベクトルから期待するフレームと診断値を再現できる。
