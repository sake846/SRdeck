# 回帰試験レビュー記録テンプレート

[回帰試験仕様](regression-test-specification.md)に従い、変更ごとにこの内容をPRまたは変更記録へコピーする。
これは変更に対する要求と証拠の対応表であり、全試験カタログではない。方式固有の入力・仕様は所有機能側へ置いて参照する。
空欄や「問題なし」だけの記載で完了とせず、未確定・未実装・未実行はそのまま記録する。
文書だけの変更では、製品の実行試験を対象外とする根拠と、リンク・コマンド・実装との整合確認を残せる。

## 1. 変更と実行対象

- 変更内容と保護する振る舞い:
- 要求の出典（文書・節、Issue等）:
- 対象コミット、試験時の未コミット差分:
- 変更ファイルと利用側を調べた方法・結果:
- 対象プラグイン／ホスト機能、能力、プロファイル、入力源:
- 記録作成者／レビュー担当:
- 総合状態: 未完了（全適用観点の証拠が揃った後に変更）

## 3. 要求と試験の対応

1行を「観点×対象×入力条件」とし、同じ試験名でも条件・アサートが異なれば行を分ける。
登録名は`RegressionTestCatalog.cs`から引用する。受入は手順書への参照を使い、架空の登録名を作らない。

| 要求の節・検査観点 | 対象と入力条件 | U/C/I/P/A | 登録名または受入手順 | コード・データと対象アサート／期待値への参照 | 実装状態 | 実行結果・証拠 |
|---|---|---|---|---|---|---|
| 未記入 | | | | | 未確認 | 未実行 |

- 実装状態: 既存で充足／追加・修正／未実装。未実装の場合は下の未充足表にも記載する。
- 実行結果: Passed／Failed（TIMEOUT含む）／Skipped／未実行。性能の一部アサートが無効なら、その指標を「未判定」と併記する。
- 対象アサートまで読んでいないものは「既存で充足」としない。試験名が一致するだけでは証拠にならない。

- OS、.NET SDK、Debug／Release、CPU／GPU／ドライバー、必要機器:

| 未充足の観点・対象 | 未実装／Failed／Skipped／未実行／未判定 | 影響・理由 | 担当 | 実施条件・期限 | 追跡先 |
|---|---|---|---|---|---|
| 未確認（確認後に具体化、未充足がなければ削除） | | | | | |

- [ ] 全観点の適否と対象外理由を確認した。
- [ ] 全適用観点を入力・アサート・実行証拠に対応付けた。
- [ ] 対象クラス・プラグイン・能力・値の列挙漏れを確認した。
- [ ] 対象コミットの検出、単独実行、Release全件と追加検証の結果を確認した（文書のみ等で対象外なら根拠を記録）。
- [ ] Skipped、未実行、無効化した判定を合格へ算入していない。
- [ ] レビュー担当が期待値の根拠と対象アサートを照合した。
- [ ] 必要な試験に未充足がなく、この変更範囲の回帰確認を完了できる。

未充足が残る場合は、追跡先があっても総合状態を「回帰確認完了」にしない。
