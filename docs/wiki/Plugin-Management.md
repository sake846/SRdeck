# プラグイン管理

SRdeckの無線方式は`SRdeckPlugin.*.dll`としてホストから分離されています。プラグインは復調コードだけでなく、設定画面、右ペイン、履歴、エクスポート、音声、周波数オーバーレイを提供できます。

## 公式パッケージの確認

`with-plugins`パッケージには、リリース時点の公開対象プラグインが含まれます。次の2か所を確認してください。

- [公式プラグイン一覧](Plugins-Overview): 用途と概要
- ZIP内の`PACKAGE-MANIFEST.json`: そのリリースに実際に含まれるDLLとバージョン

ソースツリーに存在するすべてのプラグインがバイナリ配布されるとは限りません。Meshtasticはソース公開対象ですが、公式実行ZIPには含まれません。

## DLLの検索場所

ホストは起動時に`AppContext.BaseDirectory`、通常は`SRdeck.exe`と同じフォルダーだけを非再帰で検索します。対象名は次です。

```text
SRdeckPlugin.*.dll
```

正しい例:

```text
SRdeck\
├── SRdeck.exe
├── SRdeckPlugin.Contracts.dll
├── SRdeckPlugin.Sdk.dll
├── SRdeckPlugin.Wpf.dll
├── SRdeckPlugin.Analog.dll
├── SRdeckPlugin.Ais.dll
└── SRdeckPlugin.MyDecoder.dll
```

`plugins`サブフォルダーはDLL検索先ではありません。次のフォルダーは設定、履歴、キャプチャなどのデータ用です。

```text
%LOCALAPPDATA%\SRdeck\plugins\<plugin-id>
```

「DLLの配置場所」と「プラグインデータの保存場所」を混同しないでください。

## プラグインを追加する

1. SRdeckを停止して終了します。
2. プラグインの対応ホスト版、Host API範囲、Windows x64対応を確認します。
3. 配布物をウイルス対策で検査し、ライセンスと配布元を確認します。
4. `SRdeckPlugin.<Name>.dll`と、そのプラグインだけが必要とする依存DLLを`SRdeck.exe`と同じフォルダーへ置きます。
5. SRdeckを起動します。
6. `MODE`一覧に表示名が追加されたことを確認します。
7. 低いRATEで受信開始・停止・MODE切り替えを試します。

ホットリロードはありません。DLLをコピーしただけでは、起動中のホストには読み込まれません。

## 更新する

プラグイン更新はホストとバージョンを合わせて行います。

1. SRdeckを終了します。
2. アプリケーションフォルダーをバックアップするか、新しい空フォルダーを用意します。
3. 新しいホスト一式を展開します。
4. 対応を確認したプラグイン一式を追加します。
5. 同名DLLの旧版が残っていないことを確認します。
6. 起動、検出、受信、停止、エクスポートを確認します。

`SRdeckPlugin.Contracts`、`SRdeckPlugin.Sdk`、`SRdeckPlugin.Wpf`、`SRdeckCore.SignalProcessing`はホストと共有されます。プラグインごとに異なる版を同じフォルダーへ置くと、型の不一致やロード失敗が起きます。

## 削除する

1. SRdeckを終了します。
2. 対象の`SRdeckPlugin.<Name>.dll`と、そのプラグイン専用と確認できる依存DLLをアプリケーションフォルダーから退避します。
3. SRdeckを起動し、`MODE`から消えたことを確認します。

`%LOCALAPPDATA%\SRdeck\plugins\<plugin-id>`は自動削除されません。再導入時に設定と履歴を使うなら残し、完全削除する場合は内容を確認してから別途退避／削除します。共有DLLを他のプラグイン専用と誤認して削除しないでください。

## 選択と実行

メイン画面の`MODE`は、右ペインに表示して主に動作させるプラグインを1つ選びます。ホストAPIには追加プラグインの同時アクティブ化機構がありますが、通常のMODE操作は複数プラグインをタブで同時選択する機能ではありません。

プラグインを切り替えると、前のプラグインはストリーム停止／非アクティブ化され、新しいプラグインが必要な周波数とチャネルを要求します。切り替え後は中心周波数、オーバーレイ、状態欄を確認してください。

## 互換性の確認項目

| 項目 | 確認内容 |
|---|---|
| ファイル名 | `SRdeckPlugin.*.dll`に一致 |
| プラットフォーム | Windows x64、現行.NETターゲット |
| Host API | Descriptorの最小／最大範囲に現行ホストを含む |
| プラットフォームDLL | ホストと同じリリース版 |
| ネイティブ依存 | x64 DLLとそのランタイムが揃っている |
| ID | 他プラグインと重複しない安定ID |
| エントリ | public、非abstract、非generic、引数なしpublicコンストラクター |
| 能力 | Descriptorのフラグと実装インターフェースが一致 |

## 信頼境界

プラグインはSRdeckと同じプロセス、同じユーザー権限で実行されます。サンドボックス化やホストによる署名検証はありません。導入したプラグインは、利用者がアクセスできるファイル、デバイス、ネットワークへアクセスできます。

- 信頼できる配布元だけを使う
- README、ライセンス、第三者通知、既知の制限を読む
- 可能ならハッシュや署名を配布元の情報と照合する
- 出所不明の依存DLLを既存フォルダーへ上書きしない
- 問題の切り分けでは、クリーンな`host-only`フォルダーへ対象プラグインだけを追加する

## 読み込まれない場合

1. DLL名と配置階層を確認します。
2. ホストを完全に再起動します。
3. 32-bit／64-bitの混在を確認します。
4. ホストとプラットフォームDLLのリリース版を揃えます。
5. ネイティブを含む依存DLL不足を確認します。
6. クリーンなアプリケーションフォルダーで1プラグインだけ試します。
7. 開発者はDescriptor、能力フラグ、エントリクラス条件を確認します。

開発者向けの詳細は[開発概要](Developer-Overview)と[プラグインAPI仕様](https://github.com/sake846/SRdeck/blob/main/docs/plugin-interface-specification.md)を参照してください。
