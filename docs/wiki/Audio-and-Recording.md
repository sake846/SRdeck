# 音声出力とIQキャプチャ

SRdeckでは、復調済み音声の再生と、解析用IQの保存は別の機能です。音声はその場で聞くためのPCMストリーム、IQキャプチャは復調前の複素サンプルを後から調べるためのWAVです。

## 音声出力の経路

音声対応プラグインは、ホストの共通音声ルーターを通してWindowsの既定の出力デバイスへ再生します。

```text
プラグイン復調器
      |
      v
48 kHz PCM
      |
      v
SRdeck共通音声ルーター
      |
      v
Windows既定の出力デバイス
```

現在のSRdeck画面には、出力デバイスやホスト共通マスター音量を選ぶコントロールはありません。出力先、アプリ音量、デバイス音量はWindowsのサウンド設定と音量ミキサーで管理します。

## 音声対応プラグイン

| プラグイン | 音声の用途 | 主な調整 |
|---|---|---|
| Analog | AM／FM／SSBの復調音声 | ミュート、スケルチ、AFC、FMステレオ |
| ACARS | 選択チャネルの信号モニター | 音声出力、スケルチ、受信ブザー |
| AIS | 2チャネル信号のモニター | 音声出力、スケルチ、しきい値 |
| FT8 | 選択した弱信号帯域のモニター | 音声出力 |
| HFDL | 選択した地上局チャネルのモニター | 音声出力 |
| VDL Mode 2 | 選択チャネルの信号モニター | 音声出力、スケルチ |

モニター音声が聞こえることと、デジタルフレームが復号できることは同じではありません。信号が聞こえても、同期、SNR、PPM、マルチパス、CRC／FECの条件により結果が出ない場合があります。

## 音が出ないとき

次の順で確認します。

1. 音声を持つプラグインとプロファイルを選んでいるか。
2. プラグインの`音声出力`が有効か、ミュートされていないか。
3. スケルチしきい値が信号より高くないか。
4. Windowsの既定出力デバイスが意図したスピーカー／ヘッドホンか。
5. Windows音量ミキサーでSRdeckがミュートされていないか。
6. スペクトラム上で信号が受信帯域内にあるか。
7. 受信停止、MODE切り替え、デバイス再検出で音声経路を作り直す。

Bluetooth機器の切断や既定出力の変更後は、受信を停止して再開すると復旧する場合があります。

## IQキャプチャとは

対応プラグインは受信中、メモリ内に直近のIQを循環保持します。`IQ 録音 (直前N秒)`を押すと、ボタンを押した後ではなく、押す直前までの信号を保存できます。突発的なデコード失敗の調査に向いています。

| プラグイン | 保持時間 | 主な出力 |
|---|---:|---|
| ACARS | 直前3秒 | IQ WAV + 診断JSON |
| ADS-B | 直前3秒 | IQ WAV + 診断JSON |
| Analog | 直前3秒 | IQ WAV + 診断JSON |
| FT8 | 直前20秒 | IQ WAV + 診断JSON |
| HFDL | 直前3秒 | IQ WAV + 診断JSON |
| VDL Mode 2 | 直前3秒 | Raw IQ WAV + チャネルIQ WAV + 診断JSON |

AISとWi-SUNの現行設定画面には、このプリトリガーIQ保存ボタンはありません。

## 保存先とファイル

保存先はプラグインごとに分かれます。

```text
%LOCALAPPDATA%\SRdeck\plugins\<plugin-id>\captures
```

例えばAnalogは次です。

```text
%LOCALAPPDATA%\SRdeck\plugins\analog\captures
```

一般的なキャプチャには次が作成されます。

- `<name>.wav`: Iを左チャネル、Qを右チャネルへ格納したPCM WAV
- `<name>-diagnostics.json`: 中心周波数、サンプルレート、選択プロファイル／チャネル、IQメタデータ、受信器診断

VDL Mode 2は広帯域入力と抽出後チャネルの比較用に`-raw-iq.wav`と`-channel-iq.wav`を分けます。ファイル名やJSON項目はプラグインごとに異なります。

WAVには音声として再生することを目的としたデータではなく、I/Qが2チャネルで入っています。中心周波数やプロファイルなどの無線メタデータが標準WAVタグへ完全に埋め込まれるわけではないため、診断JSONを必ず一緒に保管してください。

## 保存前の注意

- キャプチャは受信中だけ実行します。
- 目的イベントの直後、循環バッファが上書きされる前に押します。
- ディスク空き容量と書き込み権限を確認します。
- ファイルを共有する前に、位置、コールサイン、機体／船舶識別子などがJSONや履歴に含まれないか確認します。
- キャプチャは長時間録音の代わりではありません。
- 現行メインUIからWAVを再び開いて再生、シーク、ループすることはできません。

## 復号履歴とエクスポート

IQキャプチャとは別に、多くのデジタルプラグインは復号結果をプラグインデータフォルダーのJSONLへ保持し、CSV／JSONへエクスポートできます。

- IQ WAV: 復調前の信号を再解析するための資料
- 診断JSON: キャプチャ時の受信条件
- JSONL履歴: 復号済みイベントを再表示する内部履歴
- CSV／JSONエクスポート: 利用者が選んだ場所へ結果を出力

不具合報告では、再現手順、SRdeckバージョン、SDR／RATE、IQ WAV、診断JSONを組み合わせると調査しやすくなります。
